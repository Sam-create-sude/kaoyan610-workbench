# 610 设计理论 · 考研备考工作台

一个基于 RAG 的个人备考助手。把老师讲义、论文、热点资料整理成知识库，
提供**对话问答、主题整理、论点扩写、答题自测**四个功能，
所有回答**只依据知识库资料**并标注来源，检索不到时直接说"没有"而不是编造。

面向浙江工业大学 610 设计基础（论述题 100 分）备考。

---

## 它解决什么问题

论述题需要「论点 + 痛点 + 阐述 + 案例」的结构化素材，而手头资料是几十份 PDF、DOCX、
图片混在一起，还有 OCR 乱码、硬换行、重复文件。人工整理一遍要很久。

这个工具把资料清洗成知识库，然后：

- 问知识点 → 只依据你的资料回答，带出处
- 点主题 → 自动读完全部资料，出 8-9 个论点
- 给论点 → 展开成阐述（两个角度）+ 案例，字数自动校验
- 做自测 → 出 610 风格大题，你写完它对照资料批改

## 架构

```
kb_core.py            内核：知识库加载 / 向量缓存 / 语义检索 / Agent 循环
  ├── kaoyan_agent.py   命令行入口
  └── server.py         网页服务入口（Python 标准库，无 Web 框架）
        └── web/index.html   单页界面（手机自适应）

知识库构建流水线（按顺序跑）：
  extract_zips.py  → 解压资料包里的 zip
  extract_docs.py  → PDF/DOCX 提取纯文本，自动跳过乱码
  ocr_images.py    → 图片用视觉模型 OCR（比传统 OCR 准很多）
  build_kb.py      → 清洗 + 切分 + 打主题标签
  enhance_kb.py    → 按语义重新归类 + 跨主题补标签
  make_deploy.py   → 生成精简发布目录
```

**关键设计：逻辑与界面分离。** 改 `kb_core.py`，命令行版和网页版同时生效。

## 快速开始

```bash
# 1. 装依赖
python -m venv .venv
.venv/Scripts/activate        # Windows
# source .venv/bin/activate   # macOS / Linux
pip install -r requirements.txt
pip install pypdf python-docx # 需要重建知识库时才装

# 2. 配置密钥
cp .env.example .env           # 然后填入你自己的两个 Key

# 3. 准备知识库
#    把你的资料整理成 data/knowledge_610.txt，一段一行
#    格式：一行一个话题，不要一行写多件事
#    也可以直接跑上面的流水线从 PDF/DOCX 自动构建

# 4. 跑起来
python kaoyan_agent.py         # 命令行版
python server.py               # 网页版，打开 http://127.0.0.1:8000
```

## 知识库格式

`data/knowledge_610.txt`，**一行一个话题**：

```
【设计与文化】设计应深入文化内涵，将文化理解为动态的、活性的精神与行为系统……
【设计与环境】可持续设计关注产品或服务在整个生命周期中对环境、社会与经济的影响……
```

行首的 `【主题】` 是主题标签，支持多个（用 `|` 分隔，如 `【设计与创新|设计与文化】`）。
检索时按主题筛选，回答时按标签标注出处。

> **一段 = 一个完整话题**，这是最重要的一条。
> 一行里混了两个话题，检索会两边都命中不准——这是实测验证过的。

## 三个关键实现经验

### 1. 切分：按语义边界切，不要按字数切

最开始按固定字数切，结果一句话被拦腰截断，检索出来的全是碎片。改成
**段落优先**——先认自然段，只有超长的段落才在段内按句号细分。

### 2. 篇幅控制：靠程序校验，不要指望模型自己数

实测：提示词写"合计 120-145 字"，模型输出过 **194 字**；改成"恰好 3 句、每句 40-48 字"
后变成 160 字。**模型对中文字数几乎无法自控，但对"删掉 42 字"这种相对指令很听话。**

所以 `kb_core.check_expand_length()` 用 Python 数出真实字数，不达标就把具体数字
喂回去让它重写，最多两次。实测三个论点全部收敛到 135-145 字。

### 3. 数据清洗是主要工作量

真实资料很脏：知网 PDF 字体映射缺失导致全乱码、从网页复制的硬换行、
同一份文件重复多份、英文摘要和参考文献混在正文里、芯片手册误入设计资料。

`build_kb.py` 里有四道过滤：中文占比、单字符重复率、关键词开头、引用编号密度。
**不做这步，后面再怎么调检索都是白费。**

## 付费门（可选）

`web/index.html` 里有一套可选的付费逻辑，用来把工具分享给别人使用：

- 20 元一次性对应当前这个 API Key，换 Key 才需要重新付费
- 付费状态记录在浏览器 `localStorage`，用**哈希指纹**标识 Key，不存明文
- `OWNER_FINGERPRIPS` 是白名单：站长自己的 Key 直接放行，不收费

**局限性要知道**：付费状态在客户端，懂技术的人可以绕过。要真正收费需要
服务端账户体系 + 支付回调。当前实现适合先验证"有没有人愿意付"。

> 仓库里**不包含**收款码图片（`web/pay-qr.jpg` 已在 `.gitignore` 里）。
> 你要用这个功能时自己放一张进去。
